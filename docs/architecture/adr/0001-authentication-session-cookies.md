# ADR-0001: Аутентификация — session cookies

- Status: accepted (2026-10-07)
- Решает: CLAUDE.md §18 (осознанный выбор механизма auth)

## Context
zIPAM — прежде всего браузерное приложение (§21). §18 запрещает брать JWT
«потому что популярно». Альтернативы: JWT (как в ETIA), OAuth/OIDC (позже).

## Decision
Django session аутентификация, HTTP-only cookie, CSRF-защита. Роли
viewer/operator/admin — через Django Groups (§19). LDAP (AD) планируется
позже как внешний auth-backend — он не меняет механизм сессий.

## Consequences
- (+) CSRF из коробки, нет рисков хранения токенов в browser storage;
- (+) LDAP подключается вторым backend'ом без переделки архитектуры;
- (–) для API-автоматизации нужны отдельные токены (запланированы, сервисные
  учётки не должны зависеть от интерактивного логина);
- требования: локальный admin-fallback при недоступном LDAP (доступность
  инфраструктурного ПО).
